ai-dev-platform 離線操作手冊

本平台保存開發流程、治理規則、模板與驗證工具。產品原始碼、SDK、規格、建置成品與簽章金鑰由產品儲存庫及其核准系統管理。

1. 用途與限制

Registry 指出一項任務需要讀取的 workflow、governance 與 template；CI、branch rule、environment reviewer 與人工審查負責強制門檻。平台不保證固定的上下文節省比例，也不判斷產品規格是否正確。

4. 建立產品

準備：Git、Bash、Python 3、PyYAML 6.0.3、GitHub CLI；Android 另需 JDK 17、SDK 36、Gradle 9.4.1；SSD 案例另需 make 與 C11 compiler。
驗證 Release：
sha256sum -c ai-dev-platform-1.5.0.zip.sha256
gh attestation verify ai-dev-platform-1.5.0.zip \
  -R JiaChangGit/ai_dev_platform-cicd-platform
安裝：解壓到暫存 bootstrap，執行 scripts/install_platform.py，先加 --dry-run，確認目標後再重跑。
初始化 Android：
cd /absolute/path/to/Work/ai-dev-platform
python3 -B scripts/init_product.py \
  --name sample-android \
  --display-name "Sample Android" \
  --domain android \
  --ci github-actions \
  --with-example \
  --dry-run
初始化 SSD：將 domain 改為 ssd-pcie-fw；依產品選擇 CI。
初始化規格手冊：使用 generic，並提供 product type、target platform、language/framework、build、test、lint、package、artifact path 九項參數；加 --with-example 會複製 spec-notes。

確認 dry-run 顯示兩個正確且不存在的目錄後，移除 --dry-run。產品不修改唯讀平台。初始化器建立兩個獨立 Git repository，但不建立遠端、不設定 branch protection、不建立 secret。

6. 三個可執行案例

SSD PCIe FW debug 與 trace

C11 host 模擬會驗證 nsid、sector count、LBA 加法溢位與 namespace 邊界；每次記錄 READ_RECEIVED 與 READ_ACCEPTED／READ_REJECTED。Trace ring 容量是 8，覆寫最舊資料。它沒有 NVMe command、PCIe link、DMA、queue、ISR、多核心同步、cross compiler 或可燒錄 image。

make -C examples/ssd-pcie-fw clean all test lint package
./examples/ssd-pcie-fw/build/ssd-pcie-fw-sample.elf

Android App

AGP 9.2.0、Gradle 9.4.1、JDK 17、SDK 36 與 built-in Kotlin。純 Kotlin render 有三項 JVM tests；Activity 把固定資料顯示在 TextView。Debug APK 不是正式發布成品。

cd examples/android-app
gradle --no-daemon :app:lintDebug
gradle --no-daemon :app:testDebugUnitTest
gradle --no-daemon :app:assembleDebug

Spec 筆記與 HTML

虛構規格固定到 SAMPLE-EVENT-EXPORT 1.0。Validator 檢查 source register、REQ ID 集合、HTML 無 script 與無外部資源；不能判斷語意、授權或驗收案例是否正確。

cd examples/spec-notes
python3 -B validate.py
python3 -m http.server 8000 --bind 127.0.0.1

完整替換清單位於 examples/ssd-pcie-fw/SAMPLE.md、examples/android-app/SAMPLE.md、examples/spec-notes/SAMPLE.md。

7. 安全、機密與證據邊界

不提交 Token、cookie、私鑰、keystore、客戶資料、內部網址、未公開漏洞或未獲准散布的規格。Public repository 的 commit、PR、Actions log、Release assets 與 transparency log 可能被複製並長期保存。

Artifact attestation 連結 workflow、repository、commit 與觸發事件，不保證成品沒有弱點，也不取代 Android App Signing、韌體簽章或 secure boot。

8. 下載、同步、設定與移除

項目處理方式

移除／排除build、dist、.gradle、local.properties、bootstrap 暫存、失效案例檔；不刪測試來繞過失敗。

10. GitHub 與 GitLab

2026-08-25 的 API 查詢顯示兩個 GitHub repositories 已設定受保護 main、required checks、review、tag ruleset 與唯讀 Actions token。Source 另有 release-build 與 release-promotion environments。GitLab 帳號尚無兩個平台鏡像；GitLab Free 不提供自動 pull mirror 或 required approval rule。

11. 常見失敗

初始化器拒絕目標目標目錄已存在，或平台不在 Work/ai-dev-platform。不要覆寫；先檢查路徑。
找不到 Gradle／SDK／compiler平台不配送產品工具鏈；依 domain standards 安裝核准版本。
封裝拒絕 dirty worktree先提交並經 PR 合併；--allow-dirty 只供本機診斷。
release readiness 失敗依錯誤補齊真實成品、hash、證據或 tag；不要略過。
GitLab 與 GitHub 分岔GitLab 鏡像不直接修改，只從 GitHub main 與 tags 推送。
