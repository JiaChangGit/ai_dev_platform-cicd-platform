ai-dev-platform 離線手冊

這套平台把開發規則、產品原始碼、建置成品與發行核准分開保存。它不代替產品規格、CI runner 或人工審查。

目的架構資料流建立案例邊界發行驗證

目的

依任務只讀必要 workflow、governance 與 template，減少重複上下文；合併與發布仍由測試、PR、branch rule 與 environment reviewer 強制。

架構

位置內容
ai-dev-platform唯讀規則與工具，不含第三方來源副本。
product-cicd-platform產品原始碼、測試與 CI。
product-releaseRelease Note、evidence 與 tag；沒有原始碼或建置成品。
CI／成品平台ZIP、APK、ELF、SBOM 與 attestation。

資料流

需求 → source PR → build／test／lint／security／package → candidate → release evidence PR → 同版 tag → environment 核准 → 正式 release。

Attestation 連結 workflow、repository 與 commit，不代表成品沒有弱點，也不取代產品原生簽章。

建立產品

cd /absolute/path/to/Work/ai-dev-platform
python3 -B scripts/init_product.py \
  --name sample-product \
  --domain generic \
  --ci github-actions \
  --dry-run

確認路徑後移除 --dry-run。不修改唯讀平台；產品入口固定讀取平行的穩定包。

案例

  • SSD PCIe 韌體：C11 trace ring buffer 與 host test。
  • Android App：AGP 9.2.0、內建 Kotlin、狀態畫面與 unit test。
  • 規格筆記：虛構規格、追溯矩陣、離線 HTML 與識別字驗證。

安全與隱私邊界

不提交 Token、私鑰、cookie、客戶資料、內部網址或未獲准公開的規格。個人 Gmail 與 hostname 是否保留由 repository owner 決定；憑證不適用此例外。

精簡原則

平台不內含 Cookbook、第三方 skills、模型 registry 或同步腳本。歷史 blob 仍在 Git；是否重寫歷史另案處理。

發行

scripts/package_release.py 建 ZIP；scripts/install_platform.py 驗證並安裝；scripts/verify_release_layout.py 檢查 release 邊界；scripts/verify_release_evidence.py 驗證 JSON 契約、必要 checks、SHA-256 格式；scripts/verify_release_readiness.py 驗證實體 artifact／signature／SBOM／provenance。這些腳本不會連線查詢 CI run，發布者仍須到平台確認。

GitHub 與 GitLab

GitHub 是 canonical source。GitLab Free 作手動鏡像；不宣稱已完成自動 pull mirror 或免費強制 approval rule。

常見失敗

封裝拒絕 dirty worktree先 commit 並經 PR 合併；--allow-dirty 只供診斷。
release readiness 失敗依錯誤補齊真實成品、hash、證據或 tag；不要略過。
GitLab 與 GitHub 分岔GitLab 鏡像不直接修改，只從 GitHub main 與 tags 推送。

驗證

bash scripts/check.sh
python3 -B -m unittest discover -s tests -v
python3 -B scripts/audit_workspace.py /absolute/path/to/Work
python3 -B scripts/pre_push_audit.py
python3 -B scripts/package_release.py --dry-run --allow-dirty

每個「完成」結論都應附實際指令、結果與不能在線驗證的限制。
