# Workflow：除錯方法論（Debug）

> 這是通用的除錯思路，不含任何特定工具鏈的操作細節（那些屬於領域知識，見 `docs/domain-adaptation.md`）。

> 本任務在 `registry/workflow.yaml` 中標記 `handoff_required: true`：角色交接時依 `templates/task-handoff.md` 產出交接檔案，不要只靠對話上下文交接（見 `AGENTS.md` 2.1 節）。

## 步驟

1. **收集症狀**
   - 錯誤訊息、log、crash dump、使用者描述的行為，原文照抄，不要先入為主地摘要

2. **穩定重現**
   - 找出最小重現路徑；若是間歇性問題，記錄重現機率與觸發條件（負載、時序、輸入分布）

3. **建立假設清單**
   - 列出至少 2-3 個可能根因，依可能性排序，避免只鎖定第一個想到的原因

4. **二分法縮小範圍**
   - 程式碼層級：`git bisect` 找出引入問題的 commit
   - 系統層級：逐一停用或隔離模組、相依性與環境變數，觀察問題是否消失

5. **選對工具觀測**
   - 依領域選擇合適工具（例如：原生程式用 debugger/coredump，並行問題用 tracing，kernel 問題用對應子系統的除錯機制）
   - 工具的具體用法屬於領域知識，若不熟悉，先依 `docs/domain-adaptation.md` 的來源查證，不要憑印象操作可能造成破壞的指令（尤其是會影響正式環境或硬體的操作）

6. **驗證假設**
   - 每次只改一個變數，觀察結果是否符合假設；不符合就回到第 3 步修正假設，不要硬套

7. **修正與回歸測試**
   - 找到根因後，依 `workflow/bugfix.md` 的流程處理

8. **記錄**
   - 若問題重大（影響生產環境、耗費大量時間、具代表性），寫一份簡短 postmortem：時間線、根因、影響範圍、修復方式、預防措施
