# Workflow：文件撰寫與更新（Documentation）

> 文件的強制規範（何時必須更新文件、審查要求）見 `governance/documentation.md`。

> 本任務在 `registry/workflow.yaml` 中標記 `handoff_required: true`：角色交接時依 `templates/task-handoff.md` 產出交接檔案，不要只靠對話上下文交接（見 `AGENTS.md` 2.1 節）。

## 步驟

1. **確認讀者是誰**
   - 使用者？其他開發者？未來維護者？不同讀者需要不同詳細程度與用詞

2. **確認唯一資訊來源（Single Source of Truth）**
   - 先檢查是否已有相關文件，優先更新既有文件，避免同一件事在兩處各寫一份、之後互相矛盾
   - 若發現既有文件已過時或矛盾，一併修正，不要留著不管

3. **與程式碼同步**
   - 對外行為（API、CLI、設定檔格式）的變更，必須在同一個 PR 內更新文件，不要另外拖到之後補
   - 範例程式碼要能真的執行，不要放未經驗證的片段

4. **結構原則**
   - 開頭先說「這是什麼、給誰看、什麼時候該看」
   - 步驟性內容用有序清單，選項/比較用表格，避免整段散文夾雜操作步驟

5. **審查**
   - 文件審查重點：是否正確、是否可執行（若含操作步驟）、是否有讀者會看不懂的跳躍

6. **維護**
   - 重大功能異動或棄用時，主動掃過相關文件，標記或刪除過時內容，而不是等使用者回報
