# Workflow：效能測試（Benchmark）

> 本任務在 `registry/workflow.yaml` 中標記 `handoff_required: true`：角色交接時依 `templates/task-handoff.md` 產出交接檔案，不要只靠對話上下文交接（見 `AGENTS.md` 2.1 節）。

## 步驟

1. **定義指標**
   - 明確定義要量測什麼（延遲、吞吐量、記憶體用量、功耗...），以及單位
   - 定義「好」的標準是什麼（例如：P99 延遲 < 50ms，而不是「越快越好」）

2. **建立基準（Baseline）**
   - 在改動前，先在相同環境跑一次現況資料，作為對照組
   - 若沒有基準可比，至少要有理論上限或業界參考值

3. **控制環境變因**
   - 固定硬體、OS 版本、背景負載、資料集
   - 記錄所有可能影響結果的環境資訊，寫進報告（見 `templates/benchmark.md`）
   - 冷啟動 / 暖機的影響要明確排除或分開報告

4. **方法論**
   - 重複測量取多次樣本（而非單次），報告中位數與變異程度，而不是只報一個數字
   - 確認統計上的差異是否顯著，避免把雜訊當成改善

5. **執行與記錄**
   - 保留原始資料（raw data）與量測腳本，方便他人重現
   - 明確記錄使用的工具與版本

6. **分析**
   - 對照第 1 步的指標與標準，說明結論
   - 若結果不如預期，分析可能原因，而不是只呈現數字

7. **產出報告**
   - 依 `templates/benchmark.md` 撰寫，附上原始資料位置
