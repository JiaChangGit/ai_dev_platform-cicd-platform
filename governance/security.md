# Governance：安全政策（Security）

## 機密管理

- 任何密鑰、憑證、Token、內部網址、個資，一律不得寫進程式碼或提交紀錄
- 使用環境變數 / 密鑰管理服務（依部署環境選用），設定範例用 `.env.example` 而非真實值
- 建議在 CI 或 pre-commit 階段加入機密掃描；一旦誤提交，視同該密鑰已外洩，立即撤銷並更換，而不是只刪除該筆 commit

## 相依套件管理（Dependency Management）

- 定期（建議至少每月）掃描相依套件已知漏洞
- 發現高風險漏洞時，優先評估升級；若短期無法升級，記錄緩解措施與追蹤期限

## CI/CD 權限

- CI 使用的憑證採最小權限原則，依 pipeline 實際需要的範圍核發，不共用高權限帳號
- 正式環境的部署權限與一般開發權限分離

## 觸發額外安全審查的情境

出現以下改動時，`governance/review.md` 的最少核准人數規則自動提升為 2 人，其中至少 1 人需具備安全或該領域背景：
- 加密演算法、金鑰處理相關程式碼
- 身分驗證 / 授權邏輯
- 對外開放的網路介面、解析不受信任輸入的程式碼
- 涉及硬體權限邊界的程式碼（例如 kernel 特權層級、驅動程式的使用者/核心邊界）

## 弱點通報（若產品有外部使用者）

在對外文件中提供明確的弱點通報管道（例如 SECURITY.md 中的聯絡方式），並承諾回應時效；此為產品儲存庫自行建立，非本框架儲存庫範圍。
