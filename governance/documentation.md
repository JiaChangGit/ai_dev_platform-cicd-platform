# Governance：文件政策（Documentation）

> 撰寫「怎麼做」見 `workflow/documentation.md`；本文件定義**強制規則**。

## 文件即程式碼（Docs-as-code）

- 文件與程式碼同儲存庫、同 PR 流程、同審查標準
- 使用 Markdown 為預設格式，除非目標平台要求其他格式（例如需要交付 Word 文件時）

## 何時「必須」更新文件

以下變更若未同步更新文件，PR 不得合併：
- 對外 API（含 CLI 參數、設定檔欄位）新增、修改、移除
- 安裝 / 部署步驟改變
- 架構層級變更（需同步更新或新增 ADR）

## 風格

- 專案自有內容一律採用台灣繁體中文；固定術語與英文關鍵字寫法見 `docs/terminology.md`
- 每份文件開頭先說明用途、適用對象與不適用範圍
- 同一概念固定使用同一個中文詞；第一次出現時可補英文關鍵字，之後不要中英交替指同一件事
- 操作步驟使用有序清單；可執行的指令必須能直接複製執行
- 三個以上階段、分支或跨儲存庫交接，應使用 Mermaid 圖呈現；簡單對照使用表格
- 句子直接描述條件、動作與結果，不使用宣傳語、擬人語或沒有資訊量的開場語

## 審查

文件變更適用 `governance/review.md` 的一般門檻；純文件修正（錯字、連結修復）可簡化為 1 人快速核准。

## 過時內容稽核

建議每次 minor 版本發布前，掃過受影響模組的文件，確認沒有描述已移除或已改變行為的內容。發現過時內容應直接修正或標記 `deprecated`，不留著不處理。
